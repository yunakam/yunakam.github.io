# 切手計算

手持ちの切手と目標郵便料金を入力するだけで、最少枚数の切手組み合わせを即座に提案するAndroidアプリです。  
郵便を送る直前や郵便局の窓口前など、数秒以内に判断したい場面をサポートします。

## 機能概要

- **最適組み合わせの計算** — 目標金額と手持ち切手の額面・枚数を入力し、最少枚数の組み合わせを提案
- **多段階の最適化基準** — 枚数最小化を優先し、同条件では超過金額・合計金額の順で最適解を選択
- **枚数上限の設定** — 使用する切手の最大枚数をオプションで制限
- **オフライン動作** — 全計算処理をデバイス上で実行（インターネット接続不要）
- **高速計算** — 目標金額¥3,000以下・20種類以下の条件で100ms未満
- **結果の共有** — クリップボードへのコピーで結果を共有

## 使用技術

| カテゴリ     | ライブラリ / モジュール        | 選定理由                                                     |
| ------------ | ------------------------------ | ------------------------------------------------------------ |
| UI           | Jetpack Compose + Material3    | 状態駆動UIで入力フォームと結果表示の切り替えが容易           |
| ロジック     | `core` モジュール（独立）      | UIと切り離してソルバーを実装し、ユニットテストを独立して実施 |
| アルゴリズム | 動的計画法（有界コイン最適化） | 有限枚数の切手を扱う有界ナップサック問題として高速に解く     |
| 永続化       | Jetpack DataStore              | 非同期・Flowベースでスレッドセーフな設定保存                 |

## 実装ポイント

### 1. 動的計画法による有界コイン最適化

切手には1枚・2枚などの枚数制限があるため、通常のコイン問題ではなく有界ナップサック問題としてDPで解いています。目標金額¥3,000以下・20種類以下の条件では計算時間100ms未満を実現し、UIのブロッキングを防いでいます。

### 2. 多段階の最適化基準

「枚数を最小化する」だけでなく、同枚数の解が複数ある場合に「超過金額が少ない方を優先」→「それでも同じなら合計金額が少ない方を優先」という3段階の優先順位を設けています。ユーザーが直感的に納得できる結果を返すための設計です。

### 3. `core` モジュールによるロジックの分離

ソルバーロジックをAndroidフレームワークに依存しない `core` モジュールに切り出すことで、JVMのみで動作するユニットテストを高速に実行できる構成にしています。

## ユーザーセットアップ

1. アプリをインストールして起動
2. 目標郵便料金を入力
3. 手持ちの切手の額面と枚数を追加
4. 「計算」ボタンをタップして最適な組み合わせを確認

## 動作環境

- Android 8.0 (API 26) 以上
